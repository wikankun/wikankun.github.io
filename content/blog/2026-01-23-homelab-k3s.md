## Setting Up k3s for Homelab

After setting up [[2026-01-22-hyper-v-ubuntu]], I decided to go with k3s instead of Docker Compose for my homelab. Here's how I did it.

---

### Why k3s

I started with Docker Compose, but k3s gives me:

- Better resource management
- Proper orchestration for multiple services
- Easy scaling when I need it
- Closer to production environment

k3s is a lightweight Kubernetes distribution from Rancher. It's perfect for homelab and edge computing.

---

### Environment

- Ubuntu Server VM on Hyper-V
- 8 GB RAM
- Single-node k3s cluster
- Access apps via `homelab.local:port`

---

### Install k3s

Installation is straightforward:

```
curl -sfL https://get.k3s.io | sh -
```

That's it. k3s will be installed and started automatically.

Check if it's running:

```
sudo systemctl status k3s
```

---

### Core Kubernetes Concepts You Need to Know

Kubernetes has some concepts that you need to understand:

- **Pod**: One or more containers running together
- **ReplicaSet**: Keeps X pods running
- **Deployment**: Manages ReplicaSets (for stateless apps)
- **StatefulSet**: Like Deployment but for apps with identity + storage (databases)
- **Service**: Exposes your application to the network

Most of the time:
- Web apps → Deployment
- Databases → StatefulSet

### Deploying Applications

#### From YAML

```
kubectl apply -f app.yaml
```

#### From Docker Compose

If you have existing Docker Compose files, use Kompose to convert:

```
kompose convert
kubectl apply -f .
```

### Common Gotcha: Service Type

One thing that tripped me up initially was the Service type. By default, k3s creates a `ClusterIP` service, which is only accessible inside the cluster.

If you run:
```
kubectl get svc
```

And see:
- `TYPE: ClusterIP`
- `EXTERNAL-IP: <none>`

Your app won't be accessible from your machine.

---

### Using NodePort

For homelab, **NodePort** is the simplest option. It exposes your app on a specific port on the node.

Example service:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: hello
spec:
  type: NodePort
  selector:
    app: hello
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30080
```

Apply it:

```
kubectl apply -f hello-service.yaml
```

Access your app at:
```
http://homelab.local:30080
```

---

### NodePort Rules

- Allowed range: **30000-32767**
- You can't use port 80 or 8000 directly
- Each app needs its own NodePort

This is a Kubernetes rule, not k3s-specific.

---

### Enable hostname with `.local`

To make your VM accessible via `homelab.local`:

```
sudo apt install avahi-daemon
sudo systemctl enable --now avahi-daemon
hostnamectl set-hostname homelab
```

Now you can access it via `homelab.local` from any device on your network. No `/etc/hosts` edit needed.

---

### `.local` Gotcha

`.local` uses mDNS (multicast DNS), not traditional DNS.

- Works well on Linux, macOS, mobile
- **Windows is unreliable for subdomains**

This works fine:
```
homelab.local
```

This is NOT reliable on Windows:
```
app.homelab.local
```

---

### Using Friendly Ports (8000 instead of 30080)

The NodePort range (30000-32767) isn't exactly memorable. I prefer standard ports like 8000, 3000, etc.

Here's the trick: use iptables to forward port 8000 to NodePort 30080:

```
sudo iptables -t nat -A PREROUTING -p tcp --dport 8000 -j REDIRECT --to-port 30080
```

Now access your app at:
```
http://homelab.local:8000
```

Make it persistent:

```
sudo apt install -y iptables-persistent
sudo netfilter-persistent save
```

This survives reboots.

Simple. Predictable. Docker Compose vibes.

### Why Not Ingress?

Ingress is great for production, but for homelab it's overkill when:

- You have a single VM
- You're comfortable with port numbers
- You don't want to manage DNS or edit hosts files
- You just want things to work

I'll revisit Ingress when I have:
- Many apps running
- Need HTTPS everywhere
- Real DNS setup (Pi-hole / AdGuard)

### Final Thoughts

This setup is:
- Simple
- Stable
- Easy to understand
- Good enough for homelab

You don't need complex architecture for a homelab. NodePort + fixed ports + `.local` hostname is all you need to get started. You can always upgrade to Ingress later when you actually need it.
